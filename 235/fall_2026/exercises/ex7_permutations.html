Learning Objectives

This exercise is the recursion lectures in code form, and it is the same shape of problem you will meet again as backtracking in Project 3. By the end of it you should be able to:

  • write a recursive function with a clear base case, a recursive case on a smaller input, and a combine step;
  • trace a recursive function on paper by drawing the call stack, one frame per call;
  • use choose, explore, undo: make a choice, recurse on what is left, then restore the state so the next choice starts fresh — the same idea as backing out of a dead end in a maze;
  • explain why pruning (refusing to follow a choice that can never succeed) makes a search faster without changing its answer;
  • modify an object in place and guarantee it is back to its original state when the function returns.
An analogy: seating a dinner party You have n guests and n chairs. Fill the chairs left to right. For chair k, try every guest who is still standing; seat one, then seat the remaining guests in the remaining chairs. When you have tried a guest, ask them to stand up again before you try the next one. A permutation is one complete seating. The “stand up again” step is the undo that makes this backtracking.

Warm-Up — Trace by Hand (not graded)

Do this on paper before you write any code. Nothing here is submitted or graded.

1. Every arrangement. List all six permutations of (1 2 3), then mark each one that has no element in its original position (that is, 1 is not first, 2 is not second, and 3 is not third). How many are left? Keep that number: it is what Task D must compute for three values.

2. The calls. Task B works on v = (1 2 3) by swapping. Complete the table. “Swap” means swap(v[k], v[i]) before the recursive call; the undo swap happens after the call returns.

Row 4 is the base case: k equals the size, so every position has been chosen. What does the function do there? Then carry the trace on until v is (1 2 3) again and the first call (k = 0, i = 0) returns. Which permutation is recorded second?

3. The one that matters. After row 5 finishes and returns to the loop in row 1, what must v be before the loop moves on to i = 1? If it is anything other than (1 2 3), the next choice is made from a scrambled vector and permutations are lost or repeated. That is why the undo swap exists.

Task A — factorial()

Return n! as a long long, recursively. Remember n! = n · (n − 1)!, and the recursion must stop. Your function is allowed to assume 0 ≤ n ≤ 20.

Hint Name the case you can answer without any more calls. Then ask: is the argument of your recursive call closer to that case than n was?

Task B — permute()

Append to out every arrangement of v[k], v[k+1], … the end of the vector, leaving v[0..k-1] where they are. Each arrangement is appended as a copy of the whole vector. Work in place: swap, recurse, undo.

The order of the results is part of the specification. For each position k, try the choices v[k], v[k+1], … in that order, by swapping the chosen element into position k. For (4 7 9) this gives (4 7 9), (4 9 7), (7 4 9), (7 9 4), (9 7 4), (9 4 7).

When the call returns, v must be exactly as it was at the start, and everything that was already in out must still be there — append to it, never clear or replace it.

Hint Your warm-up table already is the algorithm. The base case is row 4. The loop is the “i” column. The undo is whatever restores v to what it was just before the swap.

Task C — allPermutations()

Return all permutations of v, in the order Task B produces them. The parameter is passed by value, so the caller’s vector is never changed — you are free to scramble your own copy. This task is short; its point is to see how an in-place helper is wrapped in a clean interface.

Task D — countDerangements()

A derangement is a permutation in which no element ends up where it started. Count the derangements of original. The vector v starts as a copy of original; the call counts arrangements of v[k..end] with v[0..k-1] fixed, and returns the number of arrangements in which no v[j] equals original[j]. As in Task B, v must be exactly as it was when the call returns.

This is Task B with two changes: you count rather than store, and you prune. If a choice puts an element in its original position, that choice can never lead to a derangement, so do not recurse on it. For 8 values, pruning is the difference between a quick run and a very slow one.

Edge Cases to Test

Write a few small calls of your own in a scratch main before submitting. Check at least:

  • an empty vector: there is exactly one arrangement (the empty one), not zero;
  • a vector with one element;
  • permute(v, 1, out): the first element must stay put in every result;
  • a non-empty out before the call: old entries survive;
  • after every call, print v — is it unchanged?
  • factorial(20): do you get 2432902008176640000?

Permute.hpp

// Permute.hpp
// CSCI 235 -- Exercise 7: Permutations
// Provided file -- do not modify. Gradescope compiles your submission
// against the original version of this file.

#ifndef PERMUTE_HPP
#define PERMUTE_HPP

#include <cstddef>
#include <vector>

// All four functions work on vectors of DISTINCT ints (no repeated values).
// Every function is recursive. The loops you may use are the one that tries
// each choice for the current position; the repetition itself comes from
// the recursive calls.

// Task A -- n! = n * (n-1) * ... * 1, with 0! = 1.
// Precondition: 0 <= n <= 20 (20! is the largest factorial a long long holds).
long long factorial(int n);

// Task B -- append to out every arrangement of v[k], v[k+1], ..., v[size-1],
// keeping v[0..k-1] where they are. Each arrangement is appended as a full
// copy of v. Do this IN PLACE: swap elements of v, recurse, and undo the swap.
//
// Calling permute(v, 0, out) produces every permutation of v.
//
// The order of the permutations in out is part of the specification: for each
// position k, try the choices v[k], v[k+1], ... in that order, by swapping the
// chosen element into position k. When permute returns, v must be exactly as
// it was when the call began, and anything already in out must still be there.
void permute(std::vector<int>& v, std::size_t k,
             std::vector<std::vector<int>>& out);

// Task C -- return all permutations of v, in the order Task B produces them.
// v is passed BY VALUE, so the caller's vector is never touched.
std::vector<std::vector<int>> allPermutations(std::vector<int> v);

// Task D -- count the permutations of original in which NO element is in the
// position it started in. (original[j] must not appear at index j.)
//
// v starts as a copy of original. The call counts arrangements of
// v[k..size-1], keeping v[0..k-1] where they are, and returns the count.
// v must be exactly as it was when the call began once the call returns.
//
// Calling countDerangements(v, original, 0) with v == original counts all of them.
// Examples: 3 distinct values -> 2, 4 -> 9, 1 -> 0, 0 values -> 1.
int countDerangements(std::vector<int>& v, const std::vector<int>& original,
                      std::size_t k);

#endif

// Ex7Demo.cpp
// CSCI 235 -- Exercise 7: Permutations
//
// Provided file -- do not submit this. Build it with:
//
//     g++ -std=c++17 -g Permute.cpp Ex7Demo.cpp -o ex7demo
//     ./ex7demo
//
// The expected output is in demo_output.txt. Your output should match it
// exactly once all four tasks are done.

#include "Permute.hpp"

#include <iostream>
#include <vector>

static void print(const std::vector<int>& v) {
    std::cout << "(";
    for (std::size_t i = 0; i < v.size(); ++i) {
        std::cout << (i ? " " : "") << v[i];
    }
    std::cout << ")";
}

int main() {
    std::cout << "=== Task A: factorial ===\n";
    for (int n : {0, 1, 2, 3, 4, 5, 10}) {
        std::cout << "  " << n << "! = " << factorial(n) << "\n";
    }

    std::cout << "\n=== Task B: permute ===\n";
    std::vector<int> v{1, 2, 3};
    std::vector<std::vector<int>> out;
    permute(v, 0, out);
    for (const auto& p : out) {
        std::cout << "  ";
        print(p);
        std::cout << "\n";
    }
    std::cout << "  v afterwards: ";
    print(v);
    std::cout << "   (must equal the original)\n";

    std::cout << "\n=== Task C: allPermutations ===\n";
    std::vector<int> w{5, 6, 7, 8};
    auto all = allPermutations(w);
    std::cout << "  " << all.size() << " permutations of ";
    print(w);
    std::cout << "\n  first: ";
    print(all.front());
    std::cout << "\n  last:  ";
    print(all.back());
    std::cout << "\n  w unchanged: ";
    print(w);
    std::cout << "\n";

    std::cout << "\n=== Task D: countDerangements ===\n";
    for (int n = 0; n <= 5; ++n) {
        std::vector<int> base;
        for (int i = 0; i < n; ++i) {
            base.push_back(10 * (i + 1));
        }
        std::vector<int> work = base;
        std::cout << "  " << n << " values: "
                  << countDerangements(work, base, 0) << "\n";
    }
    return 0;
}
