Learning Objectives

This exercise is the Thursday lecture in code form. By the end of it you should be able to:

  • insert a node at the front, at the back, and at an arbitrary position;
  • remove a node by value, freeing exactly the memory you unhook — no leak, no double free;
  • reverse a list in place, with three pointers and no new allocation;
  • recognize how position 0 and the empty list affect which pointer must be changed, and when a general algorithm handles these boundary cases naturally;
  • order your pointer writes so that you never destroy the only pointer to something you still need.
This is not MiniVector There is no array here and no capacity. Each node is its own heap allocation, and the order of the list lives in the next pointers rather than in the arithmetic of an index.

Why copying is disabled LinkedList.hpp marks the copy constructor and copy assignment operator = delete. Deep-copying a chain of nodes is a Rule of Three problem, and it is not what this exercise is about — so rather than let you write an accidental shallow copy and spend an hour chasing the double free, the compiler simply refuses. If you see an error mentioning a deleted function, you copied a LinkedList somewhere; pass it by reference instead.

The Rule Behind Every Task

Pointer surgery, in one sentence Before you overwrite any pointer, make sure something else still holds the address you are about to lose.

Every task below is that one rule in a different disguise. The two diagrams show it for the two hardest cases — inserting between two nodes, and removing one:

Get the order backwards on the left and the tail of the list is leaked; get it backwards on the right and you read through a pointer to memory you already gave back. Neither mistake necessarily crashes, which is exactly what makes them worth practicing.

Task A — prepend()

void prepend(int value);

Insert value at the front of the list. This demonstrates one of the main advantages of linked lists: nothing shifts, nothing is reallocated, and it takes the same time whether the list holds three nodes or three million.

Requirements

  • The new node becomes the first node; the old first node follows it.
  • It must work on an empty list, with no special case needed.
  • It must run in O(1) — if your implementation walks the list, it is wrong even if the output looks right.
Hint Two pointers change: the new node's next, and head_. Decide which one to write first, and ask yourself what the other one still needs to be readable at that moment. Note that head_ is already nullptr for an empty list, which is exactly the value the new node's next should have — that is why no if is needed.

Task B — append()

void append(int value);

Insert value at the back of the list. Unlike prepend(), there is no pointer that already refers to the end, so you have to go find it.

Requirements

  • The new node becomes the last node, and its next is nullptr.
  • Appending to an empty list must work. This is a genuinely separate case.
  • The existing order must not change.
Hint You need the loop that stops on the last node, not the one that walks past it — while (curr->next != nullptr), not while (curr != nullptr). And that loop dereferences curr immediately, so it cannot be the first thing your function does when the list is empty: on an empty list there is no node whose next could be set, and head_ itself is what has to change.

Task C — insertAt()

bool insertAt(int pos, int value);

Insert value so that it ends up at index pos, counting from 0. Return true if the insert happened and false if it did not.

Requirements

  • pos == 0 inserts at the front.
  • pos == size() is legal and appends — inserting just past the last element is how you add to the end.
  • pos < 0 or pos > size() returns false and leaves the list completely unchanged.
  • A successful insert increases size() by exactly one.
Watch this one A refused insert must not leave a Node allocated. If you call new before you know the position is valid, and then return false, that node is leaked — the autograder's memory check will find it even though every value you print looks correct.
Hint You need access to both the node at the insertion position and its predecessor. Think about what prev and curr should represent when the traversal stops. Be especially careful about position 0 and pos == size().

Task D — removeValue()

bool removeValue(int target);

Remove the first node whose data equals target, free it, and return true. If no node holds that value, change nothing and return false.

Requirements

  • Only the first match is removed, even when the list holds duplicates.
  • Removing the first node must work — head_ itself changes in that case.
  • Removing from an empty list returns false and must not crash.
  • Every node you unhook must be deleted exactly once.
Hint As in insertAt(), it is useful to keep track of both the current node and its predecessor. Remember the order: unhook the node → delete it. What is different when the node being removed is the first node?

Task E — reverse()

void reverse();

Reverse the list in place: every next points the other way, and head_ ends up at what used to be the last node. No node is created, and no node is destroyed — only the arrows change.

Requirements

  • O(n) time and O(1) extra space: a fixed number of pointer variables, whatever the length.
  • Reversing an empty list, or a one-node list, must work and must not crash.
  • After reversing, the list must still be usable — in particular the new last node's next must be nullptr.
  • Reversing twice must give back the original list.
Hint Three pointers are exactly enough: the part already reversed, the node being flipped now, and the rest of the list. The order inside the loop matters: the statement that flips a node's link destroys the only record of where the rest of the list is, so something has to be holding that address before the flip happens. When the loop ends, ask yourself which of your three pointers is standing on the node that should now be first.

Task F — removeAt() (optional practice)

bool removeAt(int pos);

Remove the node at index pos, or return false if pos is out of range. This task is not graded and you do not have to define it at all.

Why it is worth doing removeAt() is Task C's walk combined with Task D's bypass-then-free. Writing it is a good way to check whether you understood both, and it is the shape of the code you will need for the Stack and Queue in the next two classes.

LinkedList.hpp — do not modify

// LinkedList.hpp
// CSCI 235 -- Exercise 4: Linked List Operations
// Provided file -- do not modify. Gradescope compiles your submission
// against the original version of this file.

#ifndef LINKEDLIST_HPP
#define LINKEDLIST_HPP

#include <string>

// A singly linked list of ints: a chain of heap-allocated nodes, each
// holding one value and the address of the next node. head_ points at the
// first node; the last node's next is nullptr; head_ == nullptr is the
// empty list.
class LinkedList {
public:
    LinkedList();      // provided -- head_ = nullptr
    ~LinkedList();     // provided -- deletes every node

    // Copying a LinkedList is out of scope for this exercise, so it is
    // disabled here. (Without a deep copy, two lists would share one chain
    // of nodes and both destructors would delete each node -- the double
    // free from Day 6.) Attempting to copy is a compile error, not a
    // run-time bug, which is exactly what you want.
    LinkedList(const LinkedList& other) = delete;
    LinkedList& operator=(const LinkedList& other) = delete;

    // ---- Implement these five in LinkedList.cpp ----
    void prepend(int value);                // Task A
    void append(int value);                 // Task B
    bool insertAt(int pos, int value);      // Task C
    bool removeValue(int target);           // Task D
    void reverse();                         // Task E

    // Task F (OPTIONAL PRACTICE -- not graded)
    bool removeAt(int pos);

    // ---- Provided observers ----
    bool empty() const;               // head_ == nullptr
    int  size() const;                // O(n): counts the nodes by walking them
    int  getEntry(int pos) const;     // 0-based; throws std::out_of_range
    std::string toString() const;     // "10 -> 20 -> 30", or "(empty)"

private:
    struct Node {
        int   data;
        Node* next;
    };

    Node* head_;
};

#endif

// LinkedList.cpp
// CSCI 235 -- Exercise 4: Linked List Operations
// Complete the TODO sections below and submit this file.

#include "LinkedList.hpp"

#include <stdexcept>
#include <string>

// ==============================================================
// PROVIDED -- you do not need to change anything above the line
// marked "TODO" further down.
// ==============================================================

LinkedList::LinkedList() : head_(nullptr) {
}

LinkedList::~LinkedList() {
    while (head_ != nullptr) {
        Node* toDelete = head_;   // remember the node to free
        head_ = head_->next;      // advance FIRST, while we still can
        delete toDelete;          // now it is safe to free it
    }
}

bool LinkedList::empty() const {
    return head_ == nullptr;
}

// Note: this walks the chain rather than returning a stored counter, so it
// always reports what the pointers actually say. A production list would
// cache the length in a data member and keep it up to date in every
// insert and remove -- one more invariant to maintain.
int LinkedList::size() const {
    int count = 0;
    for (Node* curr = head_; curr != nullptr; curr = curr->next) {
        ++count;
    }
    return count;
}

int LinkedList::getEntry(int pos) const {
    if (pos < 0) {
        throw std::out_of_range("getEntry: position must not be negative");
    }
    Node* curr = head_;
    for (int i = 0; i < pos && curr != nullptr; ++i) {
        curr = curr->next;
    }
    if (curr == nullptr) {
        throw std::out_of_range("getEntry: position past the end of the list");
    }
    return curr->data;
}

std::string LinkedList::toString() const {
    if (head_ == nullptr) {
        return "(empty)";
    }
    std::string out;
    for (Node* curr = head_; curr != nullptr; curr = curr->next) {
        out += std::to_string(curr->data);
        if (curr->next != nullptr) {
            out += " -> ";
        }
    }
    return out;
}
