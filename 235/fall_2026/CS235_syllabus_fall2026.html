Course Description

This course is the second in a three-course series and a major stepping-stone in your software development journey. The primary focus is the design and analysis of algorithms and abstract data types. It introduces elementary data structures with related algorithms and their use in problem solving, covering core concepts such as abstraction, algorithm complexity, performance analysis, and the tradeoffs between running time, storage size, clarity, and extensibility that are at the heart of software design.

As a sequel to CSCI 135, this course enhances your C++ and object-oriented programming skills by introducing templates, giving inheritance and polymorphism a dedicated lecture and an applied project, and extending your understanding of pointers and dynamic memory allocation.

Prerequisites: CSCI 135 and CSCI 150.

Course Topics

The course follows the department's established CSCI 235 curriculum with emphasis on conceptual understanding, software design, and practical problem solving. Big-O complexity analysis is woven into every topic rather than treated as a single isolated chapter.

Programming Projects

There will be four programming projects (P1 MiniVector, P2 Maze Solver, P3 Make 24, P4 Expression Evaluator), forming the core of the course. P1 is worth 10% of the course grade and is submitted in two parts: P1A (70% of P1, due Th 9/17) and P1B (30% of P1, due Th 10/1). Every program must comply with the Programming Guidelines document (posted on the course webpage). You must read this document — it contains guidelines about submission, lateness, plagiarism, grading, and logging into your Linux accounts.

Projects are cumulative in concepts and skills: ideas developed in earlier projects are reused and extended in later ones. Together, they are designed as an integrated curriculum:

  • P1A — MiniVector<int> (due Th 9/17, 70% of P1): Dynamic array for int; push_back, pop_back, operator[], automatic capacity growth; Rule of Three (deep copy, copy assignment, destructor). Teaches heap memory and amortized growth before introducing nodes.
  • P1B — MiniVector<T> (due Th 10/1, 30% of P1): Generalize the working MiniVector<int> into a class template. Motivates templates by asking: why should MiniVector only work with int?
  • P2 — Maze Solver (posted Th 10/1, due Th 10/22): Recursive DFS and queue-based BFS pathfinding; shortest-path reconstruction using a linked list; DFSSolver and BFSSolver as subclasses of an abstract MazeSolver base class — applies the polymorphism pattern from Lecture 2.
  • P3 — Make 24 Puzzle Solver (posted Th 10/29, due Th 11/19): Recursive backtracking; recursively combine numbers using arithmetic operations; explore candidate solutions; find an expression that evaluates to 24.
  • P4 — Expression Evaluator (posted Th 11/19, due Th 12/10): Shunting-Yard algorithm using two stacks; operator precedence and associativity; unary minus; error handling. Applies the stack ADT to expression parsing.

Programming projects are expected to require substantially more time than programming exercises. Start each project as soon as it is released; the full allotted time is there because you will need it.

All projects are submitted through Gradescope and are auto-graded. Programs must compile and run correctly on the Linux lab machines (Hunter North, rooms 1001B/1001C). Confirm that your code works in the Linux environment before submitting.

Note: Many exam questions will be directly based on the programming projects. Understanding your own code thoroughly is the best exam preparation.

Programming Exercises

There will be eleven short programming exercises, distributed throughout the semester. Each exercise is released on one class day and is typically due before the next class meeting; exact deadlines and times are listed on the course schedule. Exercises are submitted on Gradescope and are fully auto-graded: submit typed code files.

Exercises are intended primarily for practice and are generally much shorter than the programming projects. They are designed to scaffold directly into the upcoming project, providing targeted practice with one key concept (e.g., virtual functions and polymorphism, pointer manipulation, Big Three implementation, stack and queue operations, tree traversal). They are short — expect 1–2 functions and a set of test cases.

No late submissions are accepted for exercises, as solutions are released promptly after the due date to allow you to review and learn from them. The two lowest exercise grades are dropped; your best 9 out of 11 exercises count toward your final grade.

Suggestions for Success

  • Read ahead. Read the assigned chapters before class. Lectures assume you have seen the material; reading ahead helps you ask better questions and follow the discussion more closely.
  • Start projects early. Projects are substantial. Begin as soon as one is released — you will need the full allotted time. Leaving a project for the night before guarantees a bad experience.
  • Ask questions. Come to class prepared to ask. Visit the tutoring lab and speak with TAs face to face — they are your most immediate resource. Come to office hours for anything that needs more time. There is no shortage of help available on campus; use it.
  • Code, debug, repeat. There is no substitute for time spent writing, breaking, and fixing code. The more you practice, the more natural it becomes.
  • Attend class. Some exam questions come directly from in-class discussions and examples. Attendance is your cheapest study tool.
  • Submit on time. No late work is accepted. A working 80% solution submitted on time outscores a perfect solution submitted one day late.
  • Think beyond this course. The concepts you learn here form the foundation for upper-level computer science courses and frequently appear in technical interviews. Aim for genuine understanding rather than simply producing working code.

Academic Integrity

Hunter College regards acts of academic dishonesty (plagiarism, cheating on examinations, obtaining unfair advantage, falsification of records) as serious offenses against intellectual honesty. The college enforces the CUNY Policy on Academic Integrity and will pursue violations according to Hunter College Academic Integrity Procedures.

You are encouraged to discuss ideas with others and consult available resources and examples to inform your work. However, you must write all your code yourself. You may not give code to, or receive code from, anyone else. If you are unsure whether something is permitted, ask before doing it.

On Generative AI: You may use AI tools as a starting point or learning aid, but you must cite any AI-generated code and take full responsibility for understanding, testing, and debugging it. AI may help explain concepts, but it cannot replace understanding — you should be able to explain every line of code you submit. AI-generated code that is submitted without understanding is an integrity risk and will not reflect the skills expected of you in future coursework.

Departmental Learning Goals

This course satisfies the following learning goals as set forth by the Computer Science department. Students will develop an understanding of the basic foundations and relevant applications of mathematics and statistics as they relate to computer science, specifically by using mathematics to analyze algorithm performance. They will also understand the relationship between computer architectures and software systems, gain deep practical knowledge of C++ as a widely used programming language, and demonstrate the ability to apply principles of design and analysis in creating substantial programs.
