Overview

Task B — binaryOperation(stack<double>&, stack<char>&)

Pop one operator and two operands, compute the result, and push it back.

Operand order matters. The second operand (num2) was pushed after the first (num1), so it sits on top. Pop num2 first, then num1. Compute num1 op num2. For 5 - 3 that is 2, not -2.

Stack layout (example: evaluating 5 - 3). 
Before call:

  operands        operators
  | 3 |           | - |
  | 5 |           +---+
  +---+

Pop 3 → num2,  pop 5 → num1,  pop ‘-’ → op
Compute  num1 - num2  =  5 - 3  =  2

After call:

  operands        operators
  | 2 |           (empty)
  +---+

Throw std::runtime_error if:

  • fewer than 2 values are on the operand stack
  • the operator stack is empty
  • the operator is / and the divisor is zero
  • the operator is not one of +, -, *, / (unrecognized operator)

Task C — processString() (numbers & operators) + basic calculate()

Digit branch

When you encounter a digit character, read the complete integer that starts there — it may be more than one digit wide (e.g., 42, 123). Use the standard place-value accumulation formula: for each digit character d, update the running total with 

num = num * 10 + (d - '0');

For example, parsing "12" starting at '1':

charactercomputationnum
'1'0 × 10 + 11
'2'1 × 10 + 212

Use std::isdigit(static_cast<unsigned char>(str[i])) as the loop condition to read additional digits. Advance i for each digit consumed inside the loop. After the loop, back up one position (i--) so that the outer i++ in processString() does not skip the first character after the number.

Task C: push the parsed number and set prev = PreviousToken::NUMBER. Task D: additionally, if prev == UNARY_MINUS, negate the number before pushing it.

Throw if prev == NUMBER or prev == CLOSE_PAREN (two operands in a row with no operator between them).

Binary-operator branch (Shunting-Yard precedence loop)

When the previous token is a NUMBER or CLOSE_PAREN, the incoming operator is binary.

Rule of thumb — before pushing a binary operator:
Check the operator at the top of the operator stack. While the stack is not empty and its top operator has precedence greater than or equal to that of the incoming operator, pop and evaluate that operator by calling binaryOperation(). Repeat until the stack is empty or the top operator has lower precedence. Then push the incoming operator. 
while (!operators.empty() &&
       precedence(operators.top()) >= precedence(ch)) {
    binaryOperation(operands, operators);
}
operators.push(ch);
prev = PreviousToken::OPERATOR;
Use while, not if.
Example: "1 - 12 / 7 + 5" — when + arrives, the operator stack is [−, /]. Both / (precedence 2) and − (precedence 1) must be popped before pushing +. An if only pops /, leaving − and producing the wrong answer.

calculate() — Steps 1, 2, 3

Task C tests call calculate() directly, so complete all three steps below as part of Task C.

Step 1 — Parse the expression.
Call processString(expr, operands, operators) to fill the two stacks.

Step 2 — Drain the operator stack.
After processString() finishes, repeatedly call binaryOperation() until the operator stack is empty. In Task D you will extend this step by checking for an unmatched ( before each call to binaryOperation().

Step 3 — Return the result.
Verify that exactly one value remains on the operand stack (operands.size() == 1), then return it. Remove the placeholder return 0.0.

Unary minus

A - sign is unary when the parser is currently expecting an operand — that is, when prev is START, OPERATOR, or OPEN_PAREN. Do not push - onto the operator stack. Instead, set prev = PreviousToken::UNARY_MINUS. When the next number is parsed, negate it before pushing.

Any operator other than - in unary position is an error (e.g., *3, +1). Consecutive unary operators are also an error (e.g., --3): throw if prev == UNARY_MINUS when another operator arrives.

Subtle difference — prev state determines everything, not spacing:

"- -3" → ERROR
    First -: prev==START → UNARY_MINUS
    Space: skipped (prev unchanged, still UNARY_MINUS)
    Second -: prev==UNARY_MINUS → consecutive unary → throw

"3 - - 5" → VALID (= 8)
    Token 3: prev → NUMBER
    First -: prev==NUMBER → binary, push -; prev → OPERATOR
    Second -: prev==OPERATOR → unary; prev → UNARY_MINUS
    Token 5: prev==UNARY_MINUS → push −5; drain: 3−(−5) = 8
Scope limit: unary minus only before a number.
-(3+4) would require evaluating a sub-expression before negating — a different algorithm. Throw std::runtime_error if prev == UNARY_MINUS and the next character is (.

Open parenthesis (

Push ( onto the operator stack and set prev = OPEN_PAREN. Throw if prev == NUMBER or CLOSE_PAREN (missing operator before (, e.g., "2(3+4)"). Throw if prev == UNARY_MINUS (unary minus before ( is not supported, e.g., "-(3+4)").

Close parenthesis )

Drain operators until the matching ( is found, then discard it. 

while (!operators.empty() && operators.top() != '(')
    binaryOperation(operands, operators);
if (operators.empty()) throw std::runtime_error("Missing (");
operators.pop();   // discard '('
prev = PreviousToken::CLOSE_PAREN;
Common mistake in the ) handler.
A wrong but tempting version: 
while (!operators.empty()) {
    if (operators.top() == '(') throw ...;  // WRONG
    binaryOperation(...);
}
Finding ( is the success condition, not an error. Counter-example: "(-3)"—when ) arrives the only item on the operator stack is (. The wrong loop throws immediately; the correct loop stops at ( and then checks whether one was found.

Finalizing calculate()

Task D adds one guard inside the drain loop: check for an unmatched ( before each binaryOperation() call. The final size check (operands.size() != 1) was already part of Task C Step 3. 

while (!operators.empty()) {
    if (operators.top() == '(')       // unmatched open paren
        throw std::runtime_error("Unmatched (");
    binaryOperation(operands, operators);
}
if (operands.size() != 1)
    throw std::runtime_error("Invalid expression");
double result = operands.top();
operands.pop();
return result;
Why check ( before calling binaryOperation?
If an unmatched ( is on the operator stack and the operand stack has only one value, binaryOperation will throw “too few operands” before you ever identify the real problem. Checking for ( first gives the correct, informative error message.

Algorithm Reference

Stack notation

Stacks are shown bottom → top throughout this document. So [3, 4] means 3 is at the bottom and 4 is on top (4 was pushed last and will be popped first).

Naming note: operator is a reserved keyword in C++ (used for operator overloading). Name your stacks operands and operators — the plural operators is not a keyword.

The Shunting-Yard algorithm (two-stack approach)

Maintain two stacks. Scan the expression left to right; for each token:

  • Number → push onto the operand stack.
  • Operator → pop and evaluate any pending operators with equal or higher precedence, then push the new operator.
  • ( → push onto the operator stack (barrier).
  • ) → drain until the matching (; discard the (.

After scanning: drain all remaining operators; the operand stack holds the result.

Walkthrough: 3 * (4 + 2)

Walkthrough: 2 + 3 * 4 - 5 — why the loop condition matters

When - arrives, the condition while (!operators.empty() && precedence(top) ≥ precedence(incoming)) triggers two pops before pushing -: first * (higher precedence), then + (equal precedence, left-to-right associativity). An if would only pop one.

Both parts of the loop condition are essential.
!operators.empty() — without this guard, the second iteration would call operators.top() on an empty stack (undefined behavior).
precedence(top) ≥ precedence(incoming) — the ≥ (not just >) ensures left-to-right order: equal-precedence operators are evaluated left to right, so + is popped before - is pushed.

Unary minus

A - sign is unary or binary depending on the previous token state — not on whether it is surrounded by spaces.

prev stateRole of -Example
STARTunary-3
OPEN_PARENunary(- 5)
OPERATORunary3 * -2
NUMBERbinary3 - 2
CLOSE_PARENbinary(1+2) - 1
Subtle difference (repeated from Task D for emphasis):

"- -3" is ERROR: first - sets UNARY_MINUS; space is skipped; second - sees prev==UNARY_MINUS → consecutive unary → throw.

"3 - - 5" is VALID (= 8): first - is binary (prev==NUMBER), sets OPERATOR; second - is unary (prev==OPERATOR), sets UNARY_MINUS; 5 becomes -5; drain evaluates 3 − (−5) = 8.

Rule: what matters is the prev state before the - arrives, not the surrounding whitespace.

Complexity Analysis

Let n = number of characters in the input string.

ResourceBoundWhy
Time — O(n) O(n) Each character is examined only a constant number of times. Each operator is pushed onto the operator stack at most once and popped at most once, and each call to binaryOperation() removes one operator. Therefore, the total work is O(n).
Space — O(n) O(n) The two stacks together hold at most O(n) elements, bounded by the number of tokens in the expression (at most n). No auxiliary arrays are allocated; the input string itself is O(n).
Intuition. Although the scan contains inner while loops (for reading multi-digit numbers and for popping operators), the total work is still linear. Each input character is examined only a constant number of times, and each operator is pushed onto and popped from the operator stack at most once. Therefore, the total running time is O(n).

// ── PreviousToken ─────────────────────────────────────────────────────────────
// Tracks the kind of token most recently parsed.
// processString() uses this to decide whether '-' is unary negation or
// binary subtraction, and to detect malformed expressions.
enum class PreviousToken {
  START,        // beginning of the expression
  NUMBER,       // just processed a number (operand)
  UNARY_MINUS,  // just processed unary '-', waiting for a number
  OPERATOR,     // just processed a binary operator
  OPEN_PAREN,   // just processed '('
  CLOSE_PAREN   // just processed ')'
};

                     std::stack<double>& operands,
                     std::stack<char>&   operators);
double calculate(const std::string& expr);

        std::cout << "FAIL: calculate(\"" << expr << "\") threw unexpectedly: "
                  << e.what() << "\n";
      }
    };

    // Valid — parentheses (6)
    chk("2*(1+3)",                   8);
    chk("(1+3)*2",                   8);
    chk("((4+3)/(3*2))",       1.16667);
    chk("(1+2*3)",                   7);
    chk("7+((4+3)-(3*2))",           8);
    chk("((3))",                     3);   // nested parens around single number

    // Valid — unary minus (12)
    // ┌─ SUBTLE DIFFERENCE ─────────────────────────────────────────────────┐
    // │  "- -3"   is an ERROR:  first '-' → UNARY_MINUS; second '-' arrives  │
    // │           while prev==UNARY_MINUS → consecutive unary → throw.        │
    // │  "3 - -5" is VALID:     first '-' is BINARY (prev==NUMBER) → OPERATOR;│
    // │           second '-' arrives while prev==OPERATOR → UNARY_MINUS;      │
    // │           '5' is negated to -5; result 3-(-5)=8.                      │
    // │  Rule: what matters is prev *before* the '-' arrives, not spacing.    │
    // └─────────────────────────────────────────────────────────────────────┘
    chk("-3",          -3);
    chk("-3-(-2)",     -1);
    chk("-3--5",        2);   // -3 - (-5) = 2
    chk("-1+3",         2);
    chk("3--2",         5);   // 3 - (-2) = 5
    chk("- 3",         -3);   // space between unary '-' and operand
    chk("3 - - 5",      8);   // binary '-', then unary '-'; 3-(-5)=8
    chk("3+-2",         1);   // binary '+', then unary '-'; 3+(-2)=1
    chk("(- 5)",       -5);   // unary '-' inside parens with space
    chk("3 + (-2)",     1);
    chk("3*-2",        -6);   // binary '*', then unary '-'
    chk("3/-2",       -1.5);  // binary '/', then unary '-'

    print_result("D valid", vpass, 18);

    // Error expressions — each must throw std::runtime_error (20 cases)
    int epass = 0, etotal = 20;

    auto chk_err = [&](const char* expr) {
      try {
        double result = calculate(expr);
        std::cout << "FAIL: calculate(\"" << expr
                  << "\") should throw but returned " << result << "\n";
      } catch (const std::runtime_error&) { epass++; }
    };

    chk_err("   ");      // whitespace-only
    chk_err("1+");       // trailing operator
    chk_err("((1+2)");   // unmatched '('
    chk_err("()");       // empty parentheses
    chk_err("*3");       // non-unary leading operator
    chk_err("-()");      // unary minus before '(' not supported
    chk_err("3 + -");    // dangling unary minus at end
    chk_err("-(3+4)");   // unary minus before '(' not supported
    chk_err("2(3+4)");   // missing operator before '('
    chk_err("(1+2)3");   // missing operator after ')'
    chk_err("(3)(4)");   // missing operator between ')' and '('
    chk_err("3 4");      // missing operator between two numbers
    chk_err("--3");      // consecutive unary minus
    chk_err("- -3");     // consecutive unary minus (with space)
    chk_err("3-");       // trailing operator (subtraction)
    chk_err("(");        // lone open paren
    chk_err(")");        // unmatched ')'
    chk_err("3/0");      // divide by zero
    chk_err("(( ))");    // parens with only whitespace inside
    chk_err("(3+)");     // missing operand before ')'

    print_result("D errors", epass, etotal);
  }

  else {
    std::cerr << "Unknown task: " << opt << "\n";
    return 1;
  }
  return 0;
}
