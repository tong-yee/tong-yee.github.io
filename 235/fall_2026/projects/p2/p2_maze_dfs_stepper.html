P2: Maze — DFS Step Visualizer

Traces the recursive helper behind DFS_Solver::getPath(): each call marks its cell visited, then tries the neighbors in the order left, right, up, down. A call that reaches the end pushes it on the answer stack; every caller that then sees a non-empty answer stack pushes its own cell. A call that finds no way forward returns without adding anything.
DFS call tree (parent call → child call; an edge appears when the child call begins)

Step-by-step trace
    cell involved in this step waiting on the recursion stack dead end (returned, nothing pushed) on the route (pushed on answer stack) destination reached wall never visited
    The small number in a corner of a cell is its recursion depth (the start call is depth 1). A blank cell with no border (ragged maze) is not part of the maze: that row is simply shorter there.
    On a return step the call has already left the recursion stack, but its cell stays highlighted so you can see which call just finished. This visualizer's JavaScript helper returns true/false internally, while the C++ helper signals success by leaving the answer stack non-empty; both produce exactly the same trace.
    Notice that dead-end cells are never pushed on the answer stack, so they cannot appear in the final route. Only the cells that were still waiting on the recursion stack when the destination was reached end up in the answer.
    Press Space or → to step forward, ← to step back, R to restart, 1–4 to switch example.
