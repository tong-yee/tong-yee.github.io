P2: Maze — BFS Reachability Step Visualizer

Traces the BFS loop in reachable() for the two uniform-grid examples in maze.cpp, plus the two ragged (jagged-row) examples from maze_v2_ragged.cpp — same queue, same up/down/left/right neighbor order. For ragged mazes, each neighbor is bounds-checked against its own row's length, not one shared column count.
BFS tree (parent → child, edges appear as each cell is enqueued)
Queue (FIFO, drawn left-to-right)
HEAD = next to dequeue · TAIL = most recently enqueued
Step-by-step trace
    current (just dequeued) just enqueued target found wall never explored
    In Examples 3 and 4, a blank cell with no border is not part of the maze at all (that row is simply shorter there) — different from an unvisited open cell.
    Any other visited cell is colored by its BFS layer (distance from start, layer 1 = start itself) — same palette and same small number as the tree below, so a cell's color and its layer badge always agree.
    In the tree, node border shows algorithm state instead of layer — thick orange = current, thick amber = just enqueued, thin faded = already processed (dequeued and neighbors checked), thick green = target found. Start and target additionally get a thin navy/red outer ring, separate from that border, so identifying them never hides the state color.
