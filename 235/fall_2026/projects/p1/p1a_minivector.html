Overview

In this project you build MiniVector, a simplified dynamic array for int values. You will manage heap memory directly — allocating, growing, copying, and releasing arrays using raw pointers — before you are allowed to use std::vector.

Task B — grow(): automatic capacity doubling  (20 pts)

Implement the private helper grow(). It is called by push_back whenever the array is full (size_ == capacity_). grow() must:

  1. Allocate a new array with new_cap = capacity_ * 2 slots.
  2. Copy all size_ existing elements into the new array.
  3. Release the old array with delete[] data_.
  4. Update data_ and capacity_.

Then add one line to push_back: before storing val, check whether size_ == capacity_ and call grow() if so.

Capacity doubling trace (pushing 1, 2, 3, 4, 5): 
push_back(1)  size_=1  cap_=2     (room; no grow)
push_back(2)  size_=2  cap_=2     (room; no grow)
push_back(3)  FULL -> grow()      cap_ 2 -> 4
              size_=3  cap_=4     (stored after grow)
push_back(4)  size_=4  cap_=4     (room; no grow)
push_back(5)  FULL -> grow()      cap_ 4 -> 8
              size_=5  cap_=8
Why double? Each element is moved at most O(log n) times across all grow calls, giving amortized O(1) cost per push_back. Doubling is the same strategy used by std::vector.

Task C — pop_back and at()  (15 pts)

Implement pop_back(), which removes the last element. Because the elements before it are untouched, you only need to decrement size_. If the vector is empty, throw std::runtime_error("pop_back on empty MiniVector").

Implement at(size_t idx) (both overloads), which works like operator[] but adds a bounds check. If idx >= size_, throw std::out_of_range("index out of range").

pop_back trace: 
v = [5][10][15]   size_=3  cap_=4
v.pop_back()   -> size_=2       (15 is logically gone; data_[2] still holds 15 but is inaccessible)
v[0] == 5      (unchanged)
v.at(1) == 10  (ok — idx 1 < size_ 2)
v.at(2)        (throws: idx 2 >= size_ 2)

What throws

  • pop_back(): std::runtime_error("pop_back on empty MiniVector") when size_ == 0.
  • at(): std::out_of_range("index out of range") when idx >= size_.

Task D — Rule of Three: destructor, copy constructor, copy assignment  (15 pts)

Your MiniVector allocates memory in the constructor and in grow(). This means you must define three special member functions — the Rule of Three — so that copies are correct and memory is released exactly once.

Destructor: ~MiniVector()

Release the heap-allocated array: delete[] data_;. Without this, every MiniVector leaks memory when it goes out of scope.

Copy constructor: MiniVector(const MiniVector& other)

Create an independent copy: allocate a brand-new array of the same capacity, then copy every element from other. After construction, modifying one vector must not affect the other.

Copy assignment: MiniVector& operator=(const MiniVector& other)

First guard against self-assignment: if (this == &other) return *this;. Then release the current array with delete[] data_, allocate a new array of other.capacity_, and copy all elements. Return *this.

Why self-assignment matters. In v = v, this and &other point to the same object. If you delete[] data_ first, you then copy from already-freed memory — undefined behavior. Always guard first.
Deep copy vs. shallow copy: 
// Shallow copy (WRONG — both point to the same array):
MiniVector b;
b.data_     = a.data_;   // both a and b now share one array!
b.size_     = a.size_;
b.capacity_ = a.capacity_;

// Deep copy (CORRECT — b gets its own independent array):
b.capacity_ = a.capacity_;
b.size_     = a.size_;
b.data_     = new int[b.capacity_];
for (size_t i = 0; i < b.size_; i++) b.data_[i] = a.data_[i];

Concept Reference

The three private members

Every MiniVector object owns exactly three things:

MemberTypeMeaning
data_int*pointer to the first element of the heap-allocated array
size_size_tnumber of elements currently stored (logical size)
capacity_size_ttotal slots allocated (physical size); always ≥ size_

Heap allocation in C++

To allocate an array of n integers on the heap: int* p = new int[n];. To release it: delete[] p;. Every new[] must be paired with exactly one delete[].

Amortized O(1) push_back

Most push_back calls simply store one value: O(1). Occasionally grow() is called, which copies all elements: O(n). But because capacity doubles each time, grow is called at most O(log n) times across n pushes, so the total copy work is O(n) — amortized O(1) per push.

static int score = 0, total = 0;

template <typename T>
void chk(const std::string& label, T got, T expected) {
    total++;
    if (got == expected) { std::cout << "  [PASS] " << label << "\n"; score++; }
    else std::cout << "  [FAIL] " << label << "  expected=" << expected << "  got=" << got << "\n";
}

void chk_throw(const std::string& label, bool threw) {
    total++;
    if (threw) { std::cout << "  [PASS] " << label << " (threw as expected)\n"; score++; }
    else         std::cout << "  [FAIL] " << label << " (no exception thrown)\n";
}

void print_result(const std::string& task, int pts) {
    if (score == total)
        std::cout << "\n" << task << ": " << score << "/" << total << " passed — " << pts << "/" << pts << " points\n";
    else
        std::cout << "\n" << task << ": " << score << "/" << total << " passed — partial credit may apply\n";
    score = 0; total = 0;
}
