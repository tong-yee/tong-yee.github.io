Do not use standard-library sequence containers such as std::vector, std::list, or std::deque to store the MiniVector elements — the provided testing and error-message code may use std::string. You have already used std::vector as a standard-library container. In this project, you build a simplified version yourself so that its growth, copying, and ownership behavior — previously hidden behind the interface — becomes something you understand and can implement from the inside. Scope note. This project intentionally has a reduced interface. It does not include front() or back() — those add surface area without adding a new idea, since they're thin wrappers around access you can already get through operator[]. reserve() (Task B) and clear() (Task C) are included: reserve() centralizes the allocate/copy/free operation so that push_back() can reuse it when the array becomes full, and clear() reinforces the distinction between size and capacity by logically removing all elements while retaining the allocation. The goals here are already substantial: raw dynamic arrays, logical size versus physical capacity, geometric growth, checked and unchecked access, operator overloading, and the Rule of Three.

Task A — Construction and destruction (14 pts)

Implement the default constructor, the count constructor, and the destructor.

Every MiniVector owns exactly one heap array, pointed to by data_. The default constructor allocates a starting array of capacity 2 — not 0 — with nothing logically "in use" yet (size_ == 0). Starting at capacity 2 instead of 0 means data_ is never null, and push_back() (Task B) never needs a special case for "growing from an empty allocation." The count constructor allocates an array sized to hold count elements and value-initializes each one to 0; if count == 0, it behaves exactly like the default constructor.

MiniVector v; // data_ -> [ ?, ? ] size_=0 capacity_=2 MiniVector w(3); // data_ -> [ 0, 0, 0 ] size_=3 capacity_=3

The destructor's entire job is delete[] data_; — nothing else, since the object is about to stop existing.

Reminder: if you haven't yet, implement both overloads of operator[] first (see the Overview above). You can use them to write assertions about your constructors right away, without waiting for Task C's at().

Task B — Growth and capacity (14 pts)

Implement reserve(std::size_t newCapacity) using the allocate/copy/free pattern. Then implement push_back(int value). When the array is full, push_back() calls reserve(2 * capacity()) before inserting the new value.

reserve(newCapacity) follows the same capacity semantics as std::vector::reserve(): if newCapacity is larger than the current capacity(), allocate a new array of exactly that size, copy the existing elements into it, and free the old array. If newCapacity is not larger than the current capacity, reserve() does nothing — it never shrinks the vector, and it never changes size(). This one function contains all of the allocate/copy/free logic in Task B.

v: size=2 capacity=2 [10, 20] v.reserve(10) -> size=2 capacity=10 [10, 20, _, _, _, _, _, _, _, _] v.reserve(1) -> size=2 capacity=10 (no-op: 1 <= capacity())

push_back should not duplicate that logic. When size() == capacity(), there is no room left: call reserve(2 * capacity()) to grow — reusing the function you just wrote — and only then insert the new value. Because the default constructor already starts at capacity 2, you never need a special case for capacity 0.

push_back(10) size=1 capacity=2 [10, _] push_back(20) size=2 capacity=2 [10, 20] push_back(30) size=3 capacity=4 [10, 20, 30, _] <- reserve(4) called: 2 -> 4 push_back(40) size=4 capacity=4 [10, 20, 30, 40] push_back(50) size=5 capacity=8 [10, 20, 30, 40, 50, _, _, _] <- reserve(8) called: 4 -> 8

Error / throw conditions: no explicit error condition is required for push_back() or reserve(). Ordinary allocation failures follow the behavior of new[] (it throws std::bad_alloc, which you do not need to catch).

Design principle: put one operation in one place and reuse it. Every place MiniVector needs to grow its array — right now just push_back() — goes through reserve() rather than repeating the allocate/copy/free steps. If a future project needs, say, an insert() that also grows the array, it would call reserve() too, instead of copying the logic a third time.

Task C — Removal and checked access (14 pts)

Implement pop_back(), clear(), and both overloads of at(std::size_t idx).

operator[], which you already implemented, does no bounds checking — an out-of-range index is undefined behavior, exactly like std::vector::operator[]. at() is the checked alternative: it must throw std::out_of_range when idx >= size(), exactly like std::vector::at(). You are implementing the "safe" sibling of a function you already wrote the "fast" version of.

pop_back() has precondition !empty(). Like std::vector::pop_back(), calling it on an empty MiniVector is undefined behavior — it does not throw. pop_back() only decrements size_; it must not change capacity_ or touch the underlying array.

v: [10, 20, 30] size=3 capacity=4 pop_back() -> [10, 20] size=2 capacity=4 (capacity unchanged) at(5) -> throws std::out_of_range (5 >= size_) at(1) -> returns 20

clear() is pop_back()'s all-at-once cousin: set size_ to 0, exactly like std::vector::clear(). Unlike pop_back(), it has no precondition — calling it on an already-empty MiniVector is perfectly safe. clear() is a logical removal, not a memory release: it changes only size_. The allocated storage remains available for reuse — it must not modify capacity_ or the underlying array.

Before clear(): logical elements: [10, 20, 30] underlying array: [10, 20, 30, _] size=3 capacity=4 After clear(): logical elements: [] underlying array: [10, 20, 30, _] <- old values may still be physically present size=0 capacity=4 After push_back(99): logical elements: [99] underlying array: [99, 20, 30, _] <- slot 0 was reused size=1 capacity=4

Task D — Rule of Three (21 pts)

Implement the copy constructor and the copy-assignment operator (operator=). The destructor from Task A completes the Rule of Three.

C++ gives you two distinct operations for "make this MiniVector look like that one," and it is worth naming both explicitly:

MiniVector b(a); // copy constructor -- b does not exist yet; brand-new storage MiniVector b; b = a; // copy-assignment operator -- b already exists; its old storage must be safely replaced

Both must perform a deep copy: after b(a) or b = a, b owns its own array, completely independent of a's. Mutating b[i] afterward must never change a[i], and vice versa.

Copy constructor: allocate a new array of other.capacity(), copy other.size() elements into it, and set size_/capacity_ to match other.

Copy-assignment operator — order matters. It is tempting to write: (1) delete the current array, (2) allocate a new array, (3) copy the elements. That works — after guarding against self-assignment (v = v;) — but it has a subtle weakness: if the allocation in step 2 ever fails, you've already destroyed *this's original data in step 1. The safer order obtains the new resource before releasing the old one:

  1. guard against self-assignment (if (this == &other) return *this;)
  2. allocate a temporary new array sized to other.capacity()
  3. copy other's elements into the temporary array
  4. delete[] the old array
  5. install the new pointer, and update size_/capacity_

This "allocate-then-release" pattern is a genuinely useful habit for managing any owned resource, not just arrays — hold onto what you already have until the replacement is safely in hand.

source: [10, 20, 30] size=3 capacity=4 destination: [ 1, 2] size=2 capacity=2 destination = source; // destination: [10, 20, 30] size=3 capacity=4 (matches source, not the old destination) destination[1] = 999; // source is untouched: source[1] is still 20 <- deep-copy independence

Error / throw conditions: you do not need to catch allocation failures. If new[] fails, its exception (std::bad_alloc) is allowed to propagate. The one behavioral requirement is that self-assignment (v = v;) must leave v completely unchanged and must not corrupt or leak memory.

Algorithm Reference

Complexity Analysis

Let n = the number of elements pushed.

ResourceBoundWhy
Time per push_back — amortized O(1) O(1) amortized, O(n) worst case for any single call Most calls are O(1): there's room, so it's just a write and an increment. The expensive O(n) reallocation only happens at the doubling points. Add up the total number of element copies caused by every reallocation across n insertions: each doubling copies roughly twice as many elements as the previous one, so 2 + 4 + 8 + … < 2n. That geometric sum is O(n) — not O(n²). Dividing that O(n) total by the n insertions that caused it gives an average, or amortized, cost of O(1) per push_back.
Allocated space O(capacity()) The heap array contains exactly capacity() slots. If capacity grows only through push_back(), then capacity remains within a constant factor of size(), so the allocated space is O(n). An explicit call to reserve() may request substantially more storage.
std::vector comparison. std::vector implementations also use geometric capacity growth, although the C++ standard does not require a particular growth factor — different standard library implementations pick different constants (commonly 1.5 or 2).

Operator overloading in this project

operator[] and operator= are both examples of operator overloading: giving a built-in-looking syntax (v[idx], a = b;) a meaning specific to your class. operator[] is the simple one-liner you write directly from its declaration in MiniVector.hpp; operator= is Task D's more involved counterpart.

Concept check (ungraded reflection): Why does MiniVector need two overloads of operator[] instead of one? Why does the const version return const int& instead of int&? What would go wrong if it didn't?

MiniVector.hpp — do not modify

// File name: MiniVector.hpp
//
// CSCI 235 -- Project 1A: MiniVector (int)
// Hunter College, CUNY | Fall 2026
//
// MiniVector is a simplified, int-only stand-in for std::vector<int>.
// This header is the complete specification for MiniVector.cpp, which you
// write yourself: implement every function declared below. Do not modify
// this file -- the interface below is exactly what the autograder expects.
//
// Internally, MiniVector keeps three pieces of state:
//
//   data_      - pointer to a dynamically allocated int array on the heap
//   size_      - how many elements are actually "in use" (logical length)
//   capacity_  - how many elements the current allocation can hold before
//                we must reallocate
//
// size_ <= capacity_ always. The default constructor starts capacity_ at 2
// (never 0), so data_ is never null and push_back() never needs a special
// case for "growing from an empty allocation."
//
#ifndef MINIVECTOR_HPP
#define MINIVECTOR_HPP

#include <cstddef>

class MiniVector {
public:
    // TODO (Task A): Default constructor.
    // Allocate an array of capacity 2. size() == 0, capacity() == 2.
    MiniVector();

    // TODO (Task A): Count constructor.
    // If count > 0: allocate an array of capacity == count, and
    // value-initialize every element to 0. size() == capacity() == count.
    // If count == 0: behave exactly like the default constructor
    // (capacity() == 2), so MiniVector(0) and MiniVector() are
    // indistinguishable.
    explicit MiniVector(std::size_t count);

    // TODO (Task A): Destructor.
    // Release the heap array owned by this vector. Nothing else is needed.
    ~MiniVector();

    // TODO (Task D): Copy constructor.
    // Deep copy: allocate a new array of other.capacity(), and copy
    // other.size() elements into it. Modifying one vector must never
    // affect the other.
    MiniVector(const MiniVector& other);

    // TODO (Task D): Copy-assignment operator.
    // Deep-copy assignment. Must correctly handle self-assignment
    // (v = v;) and must not lose *this's original data if allocation
    // of the new array were to fail (allocate the replacement before
    // releasing what you currently own).
    MiniVector& operator=(const MiniVector& other);

    // Unchecked element access (like std::vector::operator[]). Passing an
    // out-of-range idx is undefined behavior. Each overload is a one-line
    // return statement in terms of data_ -- not separately graded, but
    // needed by every task below. Study both overloads: why does the const
    // one return const int& instead of int&?
    int& operator[](std::size_t idx);
    const int& operator[](std::size_t idx) const;

    // TODO (Task C): Bounds-checked element access.
    // Throw std::out_of_range if idx >= size(). Otherwise behaves like
    // operator[].
    int& at(std::size_t idx);
    const int& at(std::size_t idx) const;

    // TODO (Task B): Ensure capacity for at least newCapacity elements.
    // If newCapacity > capacity(), allocate a new array of exactly
    // newCapacity elements, copy the existing size() elements into it, and
    // free the old array. If newCapacity <= capacity(), do nothing:
    // reserve() never shrinks the vector, and never changes size().
    void reserve(std::size_t newCapacity);

    // TODO (Task B): Append value at the end.
    // If size() == capacity(), first call reserve(2 * capacity()) to make
    // room -- reserve() already contains the allocate/copy/free logic, so
    // push_back() should not duplicate it. Then store value at the end and
    // increase size() by one.
    void push_back(int value);

    // TODO (Task C): Remove the last element.
    // Precondition: !empty(). Like std::vector::pop_back(), calling this
    // on an empty MiniVector is undefined behavior -- do not add a check,
    // and do not throw. Must not change capacity().
    void pop_back();

    // TODO (Task C): Remove all elements.
    // Set size() to 0. Unlike pop_back(), clear() has no precondition --
    // calling it on an already-empty MiniVector is perfectly safe. The
    // allocated storage remains available for reuse: clear() changes only
    // size(), and must not modify capacity() or the underlying array.
    void clear();

    // One-line implementations in terms of size_ and capacity_. Not
    // separately graded, but needed by every task below.
    bool empty() const;
    std::size_t size() const;
    std::size_t capacity() const;

private:
    int* data_;
    std::size_t size_;
    std::size_t capacity_;
};

#endif

#include "MiniVector.hpp"

#include <stdexcept>

static int g_pass = 0;
static int g_total = 0;

template <typename T>
static void chk(const std::string& label, T actual, T expected) {
    ++g_total;
    if (actual == expected) { ++g_pass; return; }
    std::cout << "FAIL: " << label << " -- expected " << expected
              << ", got " << actual << "\n";
}

template <typename F>
static void chk_throws_out_of_range(const std::string& label, F&& fn) {
    ++g_total;
    try {
        fn();
        std::cout << "FAIL: " << label
                  << " -- expected std::out_of_range, but nothing was thrown\n";
    } catch (const std::out_of_range&) {
        ++g_pass;
    } catch (...) {
        std::cout << "FAIL: " << label
                  << " -- threw, but not std::out_of_range\n";
    }
}

static void print_result(const std::string& taskLabel) {
    if (g_pass == g_total)
        std::cout << "Task " << taskLabel << ": all " << g_total << " tests passed.\n";
    else
        std::cout << "Task " << taskLabel << ": " << g_pass << "/" << g_total
                  << " tests passed.\n";
}

// ── Task B: Growth and capacity (30 tests) ──────────────────────────────────
static void testTaskB() {
    MiniVector v;
    std::size_t expectedCapacities[] = {2, 2, 4, 4, 8, 8, 8, 8};
    for (int i = 0; i < 8; ++i) {
        v.push_back((i + 1) * 10);
        chk<std::size_t>("push_back #" + std::to_string(i + 1) + ": size()",
                    v.size(), static_cast<std::size_t>(i + 1));
        chk<std::size_t>("push_back #" + std::to_string(i + 1) + ": capacity()",
                    v.capacity(), expectedCapacities[i]);

        chk<int>("push_back: v[" + std::to_string(i) + "] preserved",
                 v[i], (i + 1) * 10);
    }

    MiniVector r;
    r.push_back(1);
    r.push_back(2);
    r.reserve(10);
    chk<std::size_t>("reserve(10): capacity() becomes 10", r.capacity(), 10);
    chk<std::size_t>("reserve(10): size() unchanged", r.size(), 2);
    chk<int>("reserve(10): r[0] preserved", r[0], 1);
    chk<int>("reserve(10): r[1] preserved", r[1], 2);

    // reserve() never shrinks capacity (1)
    r.reserve(1);
    chk<std::size_t>("reserve(1) < capacity(): capacity() unchanged", r.capacity(), 10);

    // reserve() requesting less than the starting capacity is a no-op (1)
    MiniVector s;
    s.reserve(0);
    chk<std::size_t>("reserve(0): capacity() unchanged (still 2)", s.capacity(), 2);

    print_result("B");
}

// ── Task C: Removal and checked access (15 tests) ───────────────────────────
static void testTaskC() {
    MiniVector v;
    v.push_back(10);
    v.push_back(20);
    v.push_back(30);

    chk<int>("at(1) valid index", v.at(1), 20);
    chk_throws_out_of_range("at(3) == size(), out of range", [&]() { v.at(3); });
    chk_throws_out_of_range("at(100) far out of range", [&]() { v.at(100); });

    MiniVector empty;
    chk_throws_out_of_range("at(0) on empty vector", [&]() { empty.at(0); });

    const MiniVector cv(3);
    chk<int>("const at(1)", cv.at(1), 0);

    std::size_t capBefore = v.capacity();
    v.pop_back();
    chk<std::size_t>("pop_back: size() decreases by 1", v.size(), 2);
    chk<std::size_t>("pop_back: capacity() unchanged", v.capacity(), capBefore);
    chk<int>("pop_back: v[0] unchanged", v[0], 10);
    chk<int>("pop_back: v[1] unchanged", v[1], 20);

    // clear(): removes all elements without touching capacity (3)
    MiniVector c;
    c.push_back(1); c.push_back(2); c.push_back(3);
    std::size_t capBeforeClear = c.capacity();
    c.clear();
    chk<std::size_t>("clear(): size() becomes 0", c.size(), 0);
    chk<std::size_t>("clear(): capacity() unchanged", c.capacity(), capBeforeClear);
    chk<bool>("clear(): empty() becomes true", c.empty(), true);

    // clear() on an already-empty vector is a safe no-op (1)
    MiniVector d;
    d.clear();
    chk<bool>("clear() on empty vector: still empty()", d.empty(), true);

    // Previously occupied storage can be reused correctly after clear() (2)
    c.push_back(99);
    chk<int>("clear() then push_back: c[0] reused", c[0], 99);
    chk<std::size_t>("clear() then push_back: size() == 1", c.size(), 1);

    print_result("C");
}

// ── Task D: Rule of Three (29 tests) ────────────────────────────────────────
static void testTaskD() {
    MiniVector a;
    a.push_back(10);
    a.push_back(20);
    a.push_back(30);

    // Copy constructor: size, capacity, elements 0-2, allocated storage (6)
    MiniVector b(a);
    chk<std::size_t>("copy ctor: size()", b.size(), 3);
    chk<std::size_t>("copy ctor: capacity()", b.capacity(), a.capacity());
    chk<int>("copy ctor: b[0]", b[0], 10);
    chk<int>("copy ctor: b[1]", b[1], 20);
    chk<int>("copy ctor: b[2]", b[2], 30);
    b.push_back(40);
    chk<int>("copy ctor: allocated storage matches copied capacity", b[3], 40);

    // Copy-constructor independence, both directions (2)
    b[0] = 999;
    chk<int>("copy ctor: independence, a[0] unaffected", a[0], 10);
    a[1] = 888;
    chk<int>("copy ctor: independence, b[1] unaffected", b[1], 20);
    a[1] = 20;  // restore for the assignment tests below

    // Assignment: size, capacity, elements 0-2, allocated storage (6)
    MiniVector destination;
    destination = a;
    chk<std::size_t>("assign: size copied", destination.size(), 3);
    chk<std::size_t>("assign: capacity copied", destination.capacity(), a.capacity());
    chk<int>("assign: element 0 copied", destination[0], 10);
    chk<int>("assign: element 1 copied", destination[1], 20);
    chk<int>("assign: element 2 copied", destination[2], 30);
    destination.push_back(40);
    chk<int>("assignment: allocated storage matches copied capacity", destination[3], 40);

    // Assignment independence, both directions (2)
    destination[1] = 999;
    chk<int>("assign: deep-copy independence (dest -> source)", a[1], 20);
    a[2] = 888;
    chk<int>("assign: deep-copy independence (source -> dest)", destination[2], 30);
    a[2] = 30;  // restore

    // Assignment into a larger destination: size, capacity, elements 0-2 (5)
    MiniVector large;
    for (int i = 0; i < 9; ++i) large.push_back(i);
    large = a;
    chk<std::size_t>("assign into larger destination: size()", large.size(), 3);
    chk<std::size_t>("assign into larger destination: capacity()", large.capacity(), a.capacity());
    chk<int>("assign into larger destination: large[0]", large[0], 10);
    chk<int>("assign into larger destination: large[1]", large[1], 20);
    chk<int>("assign into larger destination: large[2]", large[2], 30);

    // Assigning an empty source with capacity 2 into a destination with
    // capacity 10: empty, size, capacity actually replaced (3)
    MiniVector fromEmptySource;
    fromEmptySource.reserve(10);
    fromEmptySource.push_back(1);
    MiniVector emptySrc;
    fromEmptySource = emptySrc;
    chk<bool>("assign from empty: empty()", fromEmptySource.empty(), true);
    chk<std::size_t>("assign from empty: size()", fromEmptySource.size(), 0);
    chk<std::size_t>("assign from empty: capacity() == 2", fromEmptySource.capacity(), 2);

    // Self-assignment: size, capacity, elements unchanged (5)
    MiniVector self;
    self.push_back(10); self.push_back(20); self.push_back(30);
    std::size_t selfCapBefore = self.capacity();
    self = self;
    chk<std::size_t>("self-assignment: size() unchanged", self.size(), 3);
    chk<std::size_t>("self-assignment: capacity() unchanged", self.capacity(), selfCapBefore);
    chk<int>("self-assignment: self[0] unchanged", self[0], 10);
    chk<int>("self-assignment: self[1] unchanged", self[1], 20);
    chk<int>("self-assignment: self[2] unchanged", self[2], 30);

    print_result("D");
}

int main(int argc, char* argv[]) {
    if (argc != 2) {
        std::cerr << "Usage: " << argv[0] << " [A|B|C|D]\n";
        return 1;
    }
    const std::string task(argv[1]);

    if (task == "A") testTaskA();
    else if (task == "B") testTaskB();
    else if (task == "C") testTaskC();
    else if (task == "D") testTaskD();
    else {
        std::cerr << "Task must be A, B, C, or D.\n";
        return 1;
    }
    return 0;
}
